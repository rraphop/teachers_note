# 아키텍처 결정 기록 — 로컬 AI 교무수첩 (Local Teacher Notebook) v2

이 문서는 독립 재구현에서 내린 주요 결정과 그 이유를 적는다. 판단 기준은 명세의 질문들이다:
교사가 매일 빠르게 쓸 수 있는가, AI가 틀려도 원문과 기록이 안전한가, RAM 8GB·외장 GPU 없는 학교 PC에서 도는가,
학생 개인정보가 PC 밖으로 나가지 않는가, 설치 권한 없이 압축만 풀어 실행되는가.

## 1. 전체 구조

```
TeacherNotebook.exe (Tauri 2, Rust)
 ├─ 화면: React + TypeScript strict (EXE 안에 내장, 개발 서버 불필요)
 ├─ 명령 계층 commands.rs  ──  화면이 부르는 70여 개 명령
 ├─ 도메인
 │   ├─ notes.rs        원문 저장(항상 먼저) · 분류 결과 반영(한 트랜잭션)
 │   ├─ classify.rs     분류 계획(Plan) · 규칙 제안 · AI 결과 안전 검증(guard)
 │   ├─ analysis.rs     규칙 분석: 출결 사실·학생 언급·행동/기한·과거 사실·영역 단서·업무 핵심어
 │   ├─ dates.rs        한국어 날짜·시각 해석 (AI에게 날짜 계산을 맡기지 않음)
 │   ├─ text.rs         문장·절 분리, 원문 근거(2-gram 포함률)
 │   ├─ students.rs / records.rs / duties.rs / schedule.rs / reminders.rs / search.rs
 ├─ AI
 │   ├─ runtime.rs      llama-server sidecar 수명주기 (127.0.0.1 전용, 임시 인증키, Job Object)
 │   ├─ llm.rs          프롬프트·JSON 스키마·긴 기록 나누기
 │   └─ models.rs       카탈로그·다운로드(이어받기)·검증·가져오기·삭제
 ├─ 백그라운드 app.rs   AI 분류 대기열(한 번에 하나), 알림 확인(20초), AI 엔진 자동 내리기, 하루 1회 자동 백업
 └─ SQLite (rusqlite bundled, WAL, FTS5 trigram)

runtime\llama.cpp\  llama-server.exe + DLL (llama.cpp b11000 을 llvm-mingw 로 직접 빌드)
%LOCALAPPDATA%\teachers_note\  data\notebook.db, models\, backups\, rules\, logs\, webview\, settings.json
```

## 2. 결정과 이유

### D1. 원문 먼저, AI는 나중 (비동기 대기열)
- `create_note`는 원문을 `pending` 상태로 저장하고 즉시 돌아온다 (실측 5~20ms). 분류는 별도 스레드 대기열에서 한 번에 하나씩 한다.
- AI가 없거나, 엔진이 실패하거나, 앱이 분류 중에 꺼져도 원문은 남는다. 다음 시작 때 `processing` 상태는 `pending`으로 되돌려 다시 처리한다.
- 모델이 없으면 `failed` + 쉬운 이유("AI 모델이 아직 설치되지 않았습니다 …")를 저장하고, 기록 카드에 `AI로 다시 분류`·`직접 분류` 버튼을 보인다.

### D2. AI는 "제안", 규칙이 "검증" — 하이브리드 분류
작은 로컬 모델(0.5B~9B)은 한국어 메모에서 사실을 지어내거나 영역을 틀리기 쉽다. 그래서:
1. llama-server의 **JSON 스키마 제약 디코딩**(`response_format: json_schema`)으로 형식을 보장한다.
2. AI가 낸 모든 항목을 `classify::guard_llm`이 검증한다.
   - **원문 근거**: 문구의 글자 2-gram 중 85% 이상이 원문에 없으면 가장 비슷한 원문 절로 바꾸고, 근거가 없으면 버린다. 요약도 60% 미만이면 원문 첫 문장으로 대체한다.
   - **이름**: 원문에 없는 학생 이름은 버린다 (예: AI가 만든 "학생이름1").
   - **출결**: 결석·지각·조퇴·결과(교시 수식) 사실이 원문에 있을 때만 출결 영역. 부정("지각하지 않도록")과 서류 이름("결석계")은 사실이 아니다.
   - **봉사·동아리**: 원문에 그 낱말이 있을 때만.
   - **할 일**: 행동어 또는 "~까지" 기한이 있고, 과거 사실(~함, ~했음)이 아닐 때만. 학생 이름과 함께 적힌 "진로 상담"처럼 기한·의무 표현이 없으면 관찰 기록으로 본다.
   - **일정**: 날짜가 있어야 하고, "~까지"가 붙으면 일정이 아니라 기한(할 일)이다. "교과협의회"의 '협의'처럼 행사 이름 속 행동어는 행동으로 보지 않는다.
   - **여러 문장을 묶은 항목**은 문장별로 나누어 따로 검증한다.
   - **날짜·시각**은 AI가 아니라 `dates.rs`가 입력 시각 기준으로 계산한다. AI가 적은 날짜 표현은 원문에 있을 때만 참고한다.
3. AI가 놓친 것은 규칙으로 보완한다: 원문의 출결 사실, "~까지" 할 일, 날짜 있는 일정, 담당업무 핵심어.
4. 보정 내역은 `guard_notes`로 저장해 화면에 "안전 규칙이 고친 내용 n건"으로 보여 준다 (투명성).

규칙 분석은 AI가 없을 때 `직접 분류` 창에 미리 채워지는 제안으로도 쓰인다 → AI 없이도 클릭 한 번으로 정리 가능.

### D3. 파생 데이터의 정규화
- `notes`(원문)와 파생 데이터(`observations`, `tasks`, `events`, `duty_logs`, `note_students`)를 분리했다. 재분류는 해당 기록의 파생 데이터만 한 트랜잭션으로 교체한다.
- 학생 관찰(`observations`)은 **학생 × 영역 단위**다. 한 기록에서 A 학생은 출결, B 학생은 교과처럼 따로 연결된다. 학생이 없는 수업 관찰("학생들이…")은 `student_id` 없이 남기고 학생부 자료 화면에서 나중에 학생에게 연결한다.
- 동명이인: 학급(`classes`)·번호와 분리된 학생 id. 학급 없이 이름만 겹치면 자동으로 고르지 않고 "동명이인 확인 필요"로 남긴다.
- 학생부 초안(`record_drafts`)은 근거 관찰(`record_draft_sources`)을 함께 저장한다. 다른 학생의 관찰은 근거로 연결되지 않는다.
- 출처 표시: AI가 만든 항목 `ai`, 교사가 만들거나 확인해 저장한 항목 `manual`, 교사가 고친 AI 항목 `edited=1`.

### D4. 일정표의 단방향 반영
`events.layer`(annual/monthly/weekly/note) + 할 일·업무 날짜를 `schedule::layer_visible(layer, view)` 한 함수로 거른다.
연간 학사력 → 연·월·주 / 월간 계획 → 월·주 / 주간 계획 → 주 / 기록에서 찾은 일정·할 일·업무 → 월·주.
하위 계획이 연간 학사력으로 올라가는 경로 자체가 없다. 연간 보기는 학년도(3월 시작)로도 볼 수 있다.

### D5. 알림 대기열
- 할 일·일정·업무 기록마다 `remind_enabled / offsets(7·3·2·1·당일) / time / custom_at`을 저장하고, 바뀔 때마다 남은 예약을 지우고 다시 만든다(`reminders::rebuild`). 완료하면 남은 예약이 사라진다.
- 앱이 실행 중일 때 20초마다 확인해 Windows 알림을 보낸다. 앱이 꺼져 있던 동안 12시간 넘게 지난 알림은 "놓친 알림"으로 모아 한 번 알린다.
- Portable 앱은 설치 프로그램이 없어 알림 발신자(AppUserModelID)를 현재 사용자 레지스트리(HKCU)에 등록한다 (관리자 권한 불필요). 알림이 꺼져 있으면(사용자·그룹 정책) Windows가 알려 준 이유를 그대로 화면에 보여 준다.
- 한계를 숨기지 않기 위해 설정에 "창을 닫아도 알림 영역에서 계속 실행", "Windows 로그인 때 자동 시작(HKCU Run)"을 선택 기능으로 두었다.

### D6. llama.cpp 를 직접 빌드 (Visual C++ 런타임 의존 제거)
공식 Windows CPU 빌드는 `MSVCP140.dll`, `VCRUNTIME140(_1).dll`이 필요하다. 설치 권한이 없는 학교 PC에 VC++ 재배포 패키지가 없으면
AI 엔진이 `STATUS_DLL_NOT_FOUND`로 시작하지 못한다. 같은 태그(b11000) 소스를 llvm-mingw(clang 23)로 빌드하고
LLVM `libc++.dll`/`libunwind.dll`(Apache-2.0 WITH LLVM-exception, 재배포 가능)만 함께 넣었다.
- `GGML_BACKEND_DL=ON`, `GGML_CPU_ALL_VARIANTS=ON`: CPU 종류(SSE4.2~AVX-512/AMX)에 맞는 모듈을 실행 시 고른다.
- `GGML_OPENMP=OFF`(ggml 자체 스레드 풀), `LLAMA_OPENSSL=OFF`, 웹 UI 미포함.
- `scripts/prepare-runtime.ps1`이 필요한 DLL이 모두 있는지, VC++ 런타임 의존이 없는지 검사한다.

### D7. AI 엔진(sidecar) 수명주기와 보안
- 상태: Stopped → Starting → Ready → Stopping → Stopped / Failed(원인). 원인은 런타임 없음, 모델 없음, 모델 손상, 메모리 부족, 포트 충돌, CPU 미지원, 비정상 종료, 시간 초과로 구분해 쉬운 문장으로 보여 준다.
- `--host 127.0.0.1`, 실행마다 새 `--api-key`(24바이트 난수), `--offline`(인터넷 금지), `--no-webui`, `--no-slots`(요청 내용 노출 끄기), `--cache-ram 0`(8GB PC 메모리 보호), `--reasoning off`.
- 앱 안에서 Windows `GetExtendedTcpTable`로 엔진이 실제로 어느 주소에서 대기하는지 확인해 "이 PC 안에서만 접속할 수 있습니다"를 표시한다.
- Windows Job Object(`KILL_ON_JOB_CLOSE`)에 넣어 앱이 강제 종료돼도 엔진이 함께 끝난다. 정상 종료 때는 `RunEvent::Exit`에서 멈춘다.
- 필요할 때 켜고(lazy), 설정한 시간(기본 10분) 쓰지 않으면 내린다. 추론은 한 번에 하나.
- 엔진 출력은 메모리에만 잠시 두고(최근 120줄, 문제 해결 화면용) 파일로 남기지 않는다. 기술 로그에는 기록 번호·오류 종류·시간만 쓴다.

### D8. 모델 카탈로그와 다운로드
- 5단계(+대안): 초경량 Qwen2.5 0.5B / 기본 Qwen3.5 2B / 고급 Qwen3.5 4B / 최고급 Gemma 4 E4B / 울트라 Qwen3.5 9B (+ Qwen3 8B). 모두 Apache-2.0.
- 주소는 Hugging Face의 특정 커밋에 고정하고 크기·SHA-256·라이선스를 코드에 박아 둔다.
- `.part` 파일 + HTTP Range 이어받기, 일시정지, 자동 재시도(최대 5회), 저장 공간 확인, 크기·SHA-256 검증 후에만 이름을 바꿔 설치. 연결이 끊긴 뒤 이어받는 것을 로컬 HTTP 서버 시험으로 확인한다.
- **파일로 설치**: 한 교사가 받은 .gguf 를 USB로 다른 PC에 옮겨 설치(크기·SHA 검증 후 복사, 원본 보존). 학교 네트워크가 느리거나 막혀도 쓸 수 있다.
- 삭제: 엔진 중지 → 파일(.part 포함) 삭제 → 설치 기록·선택 해제 → 화면 갱신 이벤트.
- 기기 사양(CPU·RAM·DXGI GPU/VRAM·여유 공간)은 처음 한 번만 읽어 저장하고 `기기정보 다시 읽기`로만 갱신한다. 권장 모델은 RAM 기준.
- 다운로드는 Windows 시스템 프록시와 인증서 저장소(schannel)를 쓴다 (학교 SSL 검사 프록시 대응).

### D9. 데이터 위치와 Portable
- 사용자 데이터는 `%LOCALAPPDATA%\teachers_note` (저장소 이름과 같게. 기존 구현의 `TeacherNotebook` 폴더와는 따로 있다). 1.0 첫 배포까지는 `TeacherNotebookV2` 였고, 실행기와 본체가 켤 때 새 이름 폴더가 없으면 예전 폴더 이름을 바꿔(같은 드라이브라 한 번에) 옮긴다. 예전 버전이 켜져 있어 못 바꾸면 그때는 예전 폴더를 쓰고 다음에 다시 한다(`paths::pick_root`).
- 다른 프로그램이 만든 DB가 그 위치에 있으면 열지 않는다(`app_meta` 확인) — 잘못된 마이그레이션으로 기존 데이터를 망가뜨리지 않는다.
- WAL, `foreign_keys=ON`, busy timeout 5초, `PRAGMA user_version` 마이그레이션, 짧은 쓰기 트랜잭션, 하루 1회 `VACUUM INTO` 자동 백업(14개 보관).
- 모든 로컬 데이터 삭제: 확인 문구 입력 + Windows 확인 창(백엔드가 직접 띄움) → 표식 파일 → **다음 시작 때 DB를 열기 전에** 허용된 하위 경로만 지운다 (실행 중인 DB 강제 삭제 없음, 루트 밖 경로는 정규화 비교로 차단).
- WebView2 사용자 데이터도 사용자 데이터 폴더(`webview\`)에 둔다.
- EXE는 libunwind 를 정적으로 넣어(`+crt-static`) 시스템 DLL과 `WebView2Loader.dll`만 필요하다.

### D10. 화면 설계 원칙
- 모든 화면 아래에 채팅 입력창처럼 붙은 빠른 기록 입력창(0.4에서 위 → 아래로 옮김, Ctrl+Enter 저장, Ctrl+N 이동, 쓰다 만 글 자동 보관). 메뉴를 고르지 않고 적는다.
- 오늘 화면: 기한 지난 → 오늘 → 앞으로 2주 → 날짜 없는 할 일. 체크로 완료, 줄을 누르면 수정(날짜·원래 표현·알림).
- AI 결과 옆에 항상 수정 경로: 기록 카드의 `분류 수정`(항목 단위 편집), 학생 관찰의 연필, 할 일·일정·업무의 편집 창.
- 전문 용어 대신 쉬운 말: "127.0.0.1" → "이 PC 안에서만", "FTS" → "검색", "sidecar" → "AI 엔진".
- 학생부 자료는 "교사 검토용 초안" 배너, 근거 없는 표현 노란 표시, 글자 수·NEIS 방식 바이트(참고용), 복사 버튼. 자동 입력 기능은 없다.

### D11. 내보내기와 되돌리기 (0.3)
두 기능의 역할을 나눴다. **내보내기는 보관·열람·인쇄용**, **되돌리기는 백업 파일(.db)로** 한다.
엑셀로 고친 내용을 다시 들여오는 경로는 두지 않았다 (학생 id·기록 연결이 깨지기 쉬움). 명렬표 가져오기는 나이스 가져오기와 함께 따로 만든다.

- **내보내기** (`export.rs`)
  - 엑셀(.xlsx) 파일 하나에 항목마다 시트를 만든다(`rust_xlsxwriter`, MIT/Apache-2.0, 순수 Rust).
    - 첫 줄 고정·필터·가로 인쇄·머리글 반복을 넣는다.
    - 모든 칸을 문자열로 써서 수식이 되지 않는다.
  - CSV는 항목마다 파일 하나를 만든다.
    - UTF-8 BOM·CRLF로 써서 엑셀에서 한글이 깨지지 않게 한다.
    - `= + - @`로 시작하는 글에는 `'`를 붙여 수식 주입을 막는다.
  - 저장 위치는 교사가 Windows 저장 창에서 고른다.
    - 상대 경로는 거절한다.
    - 임시 파일(`.part`)에 쓴 뒤 이름을 바꿔, 반쯤 쓴 파일이 남지 않게 한다.
    - 엑셀에서 열려 있는 파일에 쓰려 하면 쉬운 오류로 알린다.
  - 명렬표의 "연락처·주소 가리기"를 켜 두면 파일에서도 가려진다.
  - 개인정보를 보호한다.
    - 화면에서 "암호가 없는 파일" 경고를 보여 준다.
    - 탐색기 열기는 이번 실행에서 내보낸 경로에만 허용한다.
    - 기술 로그에는 표·파일 개수만 쓴다.
- **되돌리기** (`backup.rs`)
  - 실행 중인 DB 를 바꾸지 않는다. 표식 파일(`RESTORE_REQUESTED`)을 남기고 다시 시작한 뒤, **DB 를 열기 전에** 교체한다 (전체 삭제와 같은 방식).
  - 교체 순서는 다음과 같다. 어느 단계에서 실패해도 원래 DB 를 그대로 둔다.
    1. 백업 사본을 검사한다(`app_meta`·`user_version`·`PRAGMA quick_check`).
    2. 지금 데이터를 `before-restore` 백업으로 저장한다.
    3. 지금 DB 묶음(본 파일·`-wal`·`-shm`)을 옆으로 옮긴다.
    4. 사본을 제자리에 넣는다.
  - 예전 버전(0.1) 백업은 열 때 마이그레이션된다.
  - 종료할 때 DB 연결을 닫아(`Db::close`) 다음 프로세스가 바로 파일을 옮길 수 있게 한다. 잠겨 있으면 최대 10초 다시 시도한다.
- **자동 백업 조건**: 기록뿐 아니라 학생·일정·할 일·업무·시간표 중 하나라도 있으면 하루 한 번 백업한다 (0.2까지는 기록이 없으면 건너뛰는 오류가 있었다).
- 자동 시험(`TN_DATA_ROOT`)에서는 한 번만 실행 제한(single-instance)을 끈다. 그래서 교사가 쓰고 있는 창을 건드리지 않고 시험할 수 있다.

### D12. 학년도 마감 기록물과 새 학년도 (0.4)
- **PDF/A-2b, Typst 조판 엔진을 라이브러리로 내장** (`pdf.rs`, `archive.rs`, `templates/archive.typ`)
  - 장기 보존용 국제 표준(ISO 19005)이다. 목차·PDF 책갈피·쪽 번호·반복 머리글·표를 조판 엔진이 만든다.
  - 쓰지 않은 방법:
    - WebView2 인쇄: PDF/A 도 책갈피도 안 된다.
    - PDF 를 직접 그리기: 줄바꿈·쪽 나눔을 새로 만들어야 한다.
  - 대가로 실행 파일이 약 11MB 커졌다(ZIP 19.6 → 30.5MB).
- **글꼴**: Windows 의 맑은 고딕(+기호·이모지 글꼴)을 읽어 쓰인 글자만 PDF 에 넣는다. 글꼴 파일을 배포하지 않는다.
  - 글꼴에 없는 글자 때문에 PDF/A 검사를 통과하지 못하면 일반 PDF 로 다시 만든다. 이때 결과 창에 "일반 PDF"로 표시한다.
- **서식과 내용 분리**
  - 서식(.typ)은 EXE 에 내장하고, 내용은 `data.json` 으로만 넘긴다.
  - 원문에 `#`·`*`·`[` 같은 글자가 있어도 서식 명령으로 해석되지 않는다(시험으로 확인).
  - 서식은 프로그램 밖 파일을 읽을 수 없다(`World::file` 이 data.json 만 허용).
- **학년도 범위**
  - 3월 1일부터 다음 해 3월 1일 전까지다.
  - 날짜가 없는 할 일·업무 기록은 만든 날로 나눈다.
  - 학년도에 걸친 일정(겨울방학)은 넣는다.
  - 보관 처리한 학생도 그 학년도 학급이면 넣는다.
  - 엑셀 내보내기도 같은 범위 거르기(`ExportOptions.school_year`)를 쓴다.
- **개인정보**
  - 학생 정보가 거의 없는 "학사·업무 기록"과 학생 정보가 있는 "학생 기록"을 두 파일로 나눴다.
  - PDF/A 는 암호를 걸 수 없으므로 보관 위치와 파기 안내를 표지·읽어보기·화면에 적었다.
  - 명렬표에는 교사가 켜 둔 항목만 넣는다.
- **무결성**: 폴더에 SHA256SUMS.txt 를 넣는다. 도중에 실패하면 이번에 만든 폴더만 지운다.
- **새 학년도 시작**
  - 먼저 `new-year` 백업을 만들어 되돌릴 수 있게 한다.
  - 학생은 지우지 않고 `archived=1` 로 보관한다(목록·분류에서 숨김, 관찰·학생부 자료는 그대로).
  - 일과 시간·시간표 복사는 `copy_semester` 를 쓰며, 이미 있는 것은 덮어쓰지 않는다.
  - 2월에 시작하면 `school_year_started` 로 "지금 쓰는 학년도"를 한 해 앞당긴다. 그래서 새로 넣는 학급은 새 학년도가 되고, 시간표 화면은 새 학년도 1학기를 연다.
  - 한 해를 넘는 값은 무시한다(실수 방지).
  - 지난 학년도 학급은 남은 학생이 없으면 학급 목록에서 뺀다.

### D13. 입력창의 시간표 문장 (0.5)
- **규칙으로만 알아본다** (`ttinput.rs`). 요일·교시·학급·과목이 분명한 형태라 AI 가 필요 없고, AI 모델이 없어도 동작한다. 기록을 저장하는 순간 바로 반영한다.
  - 요일 낱말: "월", "월요일", "화·목", "화목", "월, 수, 금" (앞이 숫자·한글이면 "10월"·"수학"의 일부로 본다)
  - 교시: "3교시", "5·6교시", "5~7교시", "방과후" / 학급: "2-1", "2학년 3반" / 장소: 괄호 또는 "~실·관·강당·운동장"
  - 과목은 낱말 단위로 읽는다 ("과학실"을 과목 '과학'으로 읽지 않음). 목록에 없는 낱말은 남은 첫 낱말로 한다.
- **정규 시간표와 하루짜리 변경을 구분한다**
  - "매주", 또는 요일만 있고 변경 낱말이 없으면 정규 시간표다. 지금 쓰는 학기(`active_semester`)의 개인 시간표 칸에 넣는다.
  - 분명한 날짜(오늘·내일·10월 5일·다음 주 수요일)나 요일에 보강·교체·자습·휴강·대강·변경 낱말이 있으면 그날 하루의 변경(`tt_entries.kind='change'`)이다. 원래 시간표는 건드리지 않는다.
  - 날짜만 있고 변경 낱말이 없으면("내일 3교시 2-1 국어") 시간표로 보지 않는다. 그 날의 일정일 수도 있기 때문이다.
- **시간표로 보지 않는 문장**: 학생 이름, 출결 사실, 지난 일(~했음), 기한(~까지), 할 일 표현이 있는 문장. "3교시 홍길동 지각"은 출결 기록이다. 평가용 기록 35개 중 어느 것도 시간표로 잡히지 않는 것을 시험으로 확인한다.
- **교사의 시간표를 덮어쓰지 않는다**
  - 빈 칸만 채운다. 같은 수업이면 비어 있는 장소만 보탠다.
  - 다른 수업이 있으면 `conflict` 로 남기고, 기록 카드·시간표 화면에서 바꾸기/그대로를 고르게 한다.
  - 기록을 지워도 이미 채운 칸은 남긴다(시간표는 교사의 것).
- **중복 방지**: 시간표 문장은 AI·규칙 분류 결과(학생 관찰·일정·할 일)에서 뺀다. 기록 전체가 시간표 문장이면 AI 분류 없이 "시간표에 반영함"으로 끝낸다.
- **교시 → 시각**
  - 일정·할 일·업무 기록 문구에 "N교시"가 있고 시각이 없으면, 그 날짜 학기의 일과 시간에서 시작 시각을 넣는다.
  - 저장하지 않은 학기는 기본 일과 시간을 쓴다.
- **표시**
  - 하루짜리 변경은 오늘 시간표의 그 교시에 "보강 1-3"처럼 겹쳐 보인다. 원래 수업은 취소선으로 표시한다.
  - 월간·주간 일정표에는 '시간표 변경' 층으로 보인다. 누르면 그 변경을 적은 기록으로 간다.

### D14. 파일 하나 버전 (0.6)
- **목표**: 바탕화면에 파일 하나만 두고 실행하고, 그 파일을 덮어써서 업데이트한다.
- **완전한 단일 실행이 불가능한 이유**
  - AI 엔진(llama-server.exe)은 따로 도는 프로세스다.
  - WebView2Loader.dll 은 본체 EXE 가 시작하기 전에 파일로 있어야 한다(gnullvm 빌드는 정적 연결 불가).
  - 그래서 **실행기 + 내장 묶음** 방식을 택했다.
- **실행기**(`launcher/`)
  - 순수 Rust, `+crt-static`. Windows 시스템 DLL(kernel32·user32·gdi32·UCRT)만 쓴다.
  - 안에 두 가지를 넣는다: 조립한 Portable 폴더 전체를 묶은 ZIP(`include_bytes!`, 1.0부터 압축하지 않음), 파일 목록과 SHA-256(`manifest.json`).
  - 켤 때 `%LOCALAPPDATA%\teachers_note\program\<버전>` 의 모든 파일을 목록과 대조한다(크기 → SHA-256, 약 0.3초).
  - 다르거나 없으면 "준비 중" 창을 띄운다. 임시 폴더에 풀고, `enclosed_name` 으로 경로 이탈을 막고, 검사한 뒤 이름을 바꿔 넣는다.
  - 두 번 눌러 동시에 풀면 먼저 끝난 쪽을 쓴다. 지난 버전 폴더는 정리한다(쓰는 중이면 다음에).
  - 본체에 `TN_LAUNCHER`(실행기 경로)를 넘긴다.
    - 본체는 자동 시작 등록에 이 경로를 쓴다. 풀린 경로를 등록하면 덮어쓰기 업데이트 뒤 끊기기 때문이다.
    - 지난 버전 경로가 등록돼 있으면 시작할 때 고친다.
- **풀 위치**
  - TEMP 가 아니라 사용자 데이터 폴더다. 지워지지 않고, 데이터와 함께 관리되며, 매번 검사한다.
  - "모든 로컬 데이터 삭제"는 실행 중인 본체가 들어 있는 program 폴더를 지우지 않는다(다음 실행 때 다시 검사).
- **검증**
  - 패키징 9단계: 처음 실행(풀기), 두 번째 실행, 손상 뒤 다시 풀기, 지난 버전 정리. 모두 `--self-test` 로 본체가 실제로 뜨는지 확인한다.
  - `scripts/e2e/single-update-test.ps1`: 시험용 바탕화면에서 실행 → 기록 → 새 버전으로 덮어쓰기 → 기록 유지·새 폴더·지난 폴더 정리.
- **위험과 대응**
  - "스스로 파일을 풀어 실행하는" 동작은 일부 백신이 의심할 수 있다(서명 없으면 더).
  - 실제로 1.0 에서 압축한 묶음(32MB)을 품은 실행기를 Windows 보안이 `Trojan:Win32/Sabsik.FL.A!ml`(기계학습 판정)로 잡아 격리했다. 본체·AI 엔진·ZIP 은 깨끗했다. 묶음을 압축하지 않으니(85MB) 같은 검사에서 깨끗했다 → 압축하지 않는다. 다만 판정 모델이 바뀌면 다시 걸릴 수 있다(근본 해결은 코드 서명).
  - 패키징 10단계에서 `MpCmdRun -DisableRemediation`(격리하지 않고 검사만)으로 실행기·ZIP·본체를 검사하고, 탐지되면 패키징을 멈춘다.
  - 그래서 ZIP 버전을 계속 함께 만든다. 두 형태는 같은 데이터 폴더를 쓰므로 오가도 기록이 이어진다.
- **파일 이름에 버전 (0.61, 1.0부터 `교무수첩_1.0.0.exe`)**: 프로그램 버전 그대로 `교무수첩_<버전>.exe`(1.0 까지는 `교무수첩(0.61).exe`). 실행기는 예전 이름도 알아보고, 같은 버전이라도 예전 이름이면 정리 대상에 넣는다. 새 버전은 덮어쓰기가 아니라 새 이름으로 옆에 생긴다. 그래서:
  - 새 버전을 처음 풀 때, 같은 폴더의 지난 버전 파일(이름의 버전이 더 낮은 것)을 휴지통으로 옮길지 묻는다. `FOF_ALLOWUNDO` 를 쓰고, 영구 삭제가 되는 경우에는 Windows 가 경고한다.
  - 지난 버전 파일을 켜면, 더 새로운 풀린 버전이 있는지 보고 새 파일을 쓰라고 묻는다.
  - 정리는 **더 오래된** 버전 폴더만 한다. 새 버전 폴더는 지우지 않는다.
  - 본체는 자동 시작이 켜져 있으면 지금 켠 파일을 가리키게 고친다.

- **방과후 요일 (0.9)**: `AfterSchool.days`·`PeriodSlot.days` (1=월 … 6=토, 비어 있으면 매일 — 예전 설정과 같게). 교시 시각을 직접 고쳐 저장해도 요일은 설정값으로 다시 맞춘다. 오늘 시간표는 그 요일에만(그날 변경이 있으면 보임), 주간 시간표는 다른 요일 칸을 막는다.
- **자동 실행·항상 위 (0.9)**: 왼쪽 메뉴 ‘설정’ 바로 아래 체크 두 개.
  - 자동 실행은 HKCU `…\CurrentVersion\Run` 의 `LocalTeacherNotebookV2` 값에 `"실행파일"`만 적는다(창을 띄운 채로 켬). 예전 `--background`(알림 영역에만) 모양은 프로그램을 켤 때 고쳐 쓴다. `--background` 인자 자체는 계속 받는다.
  - 자동 시험(`TN_DATA_ROOT` 설정)에서는 실제 시작 프로그램 목록 대신 `HKCU\Software\LocalTeacherNotebookV2-Test\Run` 에 쓴다.
  - 투명도(1.0)는 `AppSettings.window_transparency`(0~70%)에 저장하고 `window_fx.rs` 가 Windows 계층 창(WS_EX_LAYERED) 알파로 적용한다(메인 스레드에서). 70%를 넘지 못하게 해 창이 안 보이게 되는 일을 막고, 0%로 되돌리면 알파 255로 둔다(계층 스타일을 떼면 다시 그릴 때까지 깜박임). 끄는 동안 바로 보이게 마지막 값만 이어서 보내고, data-changed 는 보내지 않는다.
  - 항상 위는 `AppSettings.always_on_top` 에 저장하고 창을 만들 때·`set_always_on_top` 때 적용한다. `update_settings` 는 이 값을 바꾸지 않는다(화면에 남은 예전 설정으로 덮어쓰지 않게).
- **학사력 색 (0.9)**: 빨강은 휴일 색으로만 쓴다. 학사력 층 색은 청회색(`.layer-annual`). 오늘 화면 ‘다가오는 일정’ 점은 휴일·휴업일·방학이면 설정의 날짜 색(`AgendaItem.day_color`)이다. 학사력(연간) 달력과 기록물 PDF 학사력 달력은 일요일부터 시작하고, 일요일 날짜는 휴일 색이다. 주간·월간 표는 월요일부터.

### D15. 나이스 명렬표·학생 인식·기록 두 갈래·라이선스 (0.7)
- **나이스 명렬표 가져오기** (`neis_roster.rs`, calamine)
  - 나이스 공개 API로는 받을 수 없는 자료라 교사가 받은 엑셀 파일을 그대로 읽는다(여러 파일, 끌어다 놓기).
  - 열 순서가 출력 설정마다 달라(기본 5열, 전체 12열) **머리글 이름**으로 열을 찾는다. 공백·줄바꿈을 지우고 비교한다("주민등록번호\r\n(외국인등록번호)"). "번호"는 정확히 같을 때만 번호 열로 본다.
  - 모든 칸이 글자라 번호를 숫자로 바꿔 정렬한다. 생년월일 "2011.02.17." → 2011-02-17, 성별 남성/여성 → 남/여.
  - 같은 학생 찾기: 학생개인번호(학년이 올라가도 그대로, 보관 학생 포함) → 학급·번호·이름 → 학급·이름 → 학급 없이 자동 등록된 '확인 필요' 같은 이름(하나일 때). 정보만 보태고, 빈칸은 기존 값을 지우지 않는다. 파일 하나 = 트랜잭션 하나.
  - 개인정보: 주소·우편번호·주민등록번호는 목록에 없고 학생 상세에서 눌러야 보인다. 주민등록번호는 설정을 켤 때만, 뒷자리를 가린 모양으로만 저장하고, 끄면 저장한 값도 지운다. 분류용 명단(`students::roster`)에는 이름·학급·번호만 넣는다.
  - 실제 파일 확인은 개수만 출력하는 시험(`real_files_counts_only`, 기본 무시)으로 했다. 실제 파일은 저장소에 넣지 않는다.
- **날짜 문장의 제목과 메모** (`classify::title_and_memo`)
  - "10. 2." 의 앞 점에서 문장을 자르지 않는다(`text::sentences`). "10-2"는 7~12월이거나 바로 뒤에 시각이 올 때만 날짜로 본다.
  - 날짜가 든 절이 일정 제목이고, 같은 문장의 나머지 설명 절(할 일·일정·학생·출결이 아닌 절)은 일정 메모(`events.memo`)가 된다. 날짜·시각뿐인 절이면 바로 뒤 절을 제목으로 쓴다.
  - AI가 설명 절을 따로 일정으로 내면, 다른 일정의 메모에 든 것은 뺀다. 업무 기록에도 그 문장의 날짜를 넣는다. 카드 요약은 앞의 날짜·시각을 뗀다.
- **학생·학급 인식** (`analysis::find_students`)
  - 학급 표기 "2-1·2학년 1반·2학년1반·2학년·2년" 뒤의 이름들을 쉼표·공백으로 이어 읽어 모두에 학급을 붙인다. 명단에 없는 이름은 학급 바로 뒤나 쉼표 뒤에서만 받는다("1학년 홍길동 지도함"의 '지도함' 방지).
  - 학년만 적으면 그 학년의 학급이 하나일 때 그 학급으로 본다. 학급 구성은 분류용 명단 끝에 붙인 '이름 없는 학급 항목'(확인된 학생이 있는 학급 + 시간표의 학급)으로 전한다.
  - 두 글자 이름은 뒤가 공백·문장부호·조사(+공백)로 끊길 때만 인정하고, 이름은 긴 것부터 맞춘다.
  - 적은 학급이 명렬표와 다르면 명렬표를 따르고 `written_class` 를 남겨 '확인해 주세요' 안내를 붙인다.
  - "수업중 잠 → 지도함"처럼 이미 있었던 일(오늘·지난 날짜)은 일정이 아니다. 한 기록에서 같은 학생·같은 영역의 관찰은 하나로 합친다(`apply_plan`).
- **기록 두 갈래** (`notes.track`)
  - '정리된 업무기록' = 직접 옮긴 'work', 또는 갈래가 없고 할 일·일정·업무·관찰·시간표가 나온 기록. 나머지는 '일반 기록'.
  - 판정은 저장하지 않고 조회할 때 계산한다(`IS_WORK_SQL`). 그래서 AI가 분류하면 저절로 옮겨지고, 직접 옮긴 갈래는 다시 분류해도 바뀌지 않는다.
- **라이선스**: 프로젝트 맨 위 `LICENSE.txt`(저작권자 차일영, 무료 사용·오픈소스 아님)와 `THIRD_PARTY_NOTICES.txt`(오픈소스·AI 모델)를 프로그램에 `include_str!` 로 넣어 설정 → 라이선스 및 저작권에서 보여 주고, 패키지 맨 위에도 BOM UTF-8 로 넣는다. 실행 파일 속성에 저작권 표시를 넣었다.

### D16. 나이스 공개 API·급식·학사력·시간표 색 (0.8)
- **보내는 값**: 교육청·학교 코드, 날짜, 학교 이름(찾을 때), 인증키(넣었을 때)만. 시험(E2E)은 `TN_NEIS_BASE` 로 127.0.0.1 시험 서버만 쓸 수 있다.
- **인증키 없을 때**: 나이스는 쪽 번호와 상관없이 처음 5줄만 준다(실측: 1학년 1반 한 주 시간표 32칸 중 5칸, 학사일정 200건 중 5건). 그래서
  - 급식은 한 주씩 받는다(중식만 주는 학교는 한 주 5줄). 한 주가 5줄을 넘으면 보려는 날 하루만 더 받는다.
  - 시간표·학사일정은 키가 없으면 받지 않고 '인증키 필요'로 알린다. 여러 번 쪼개 받아 제한을 피하지 않고, 일부만 받아 틀린 시간표를 만들지 않는다.
- **시간표**: 이번 주 월요일부터 4주를 받아 학급·요일·교시마다 가장 많이 나온 과목(같으면 최근)으로 학교·학급 시간표를 만든다. 칸 출처 `source='neis'` — 다시 받으면 이 칸만 바꾸고 교사가 입력한 칸은 그대로(`INSERT OR IGNORE`). 교사가 나이스 칸을 고치면 교사 칸이 된다.
  - 개인 시간표 = 학교 시간표의 나이스 칸 중 '내 과목'이고 빼지 않은 학급인 칸. 설정을 바꾸면 인터넷 없이 다시 만든다. 겹친 칸은 알린다.
  - 나이스 학급 목록(classInfo)은 다 받았을 때만 저장해 '학년마다 반이 몇 개인지'(6번 학생 인식)에 쓴다.
- **학사일정**: 그 학년도(3월~2월)를 받는다. 종류는 방학 이름 → 휴일 이름 → 휴업일 이름 → 나이스 구분값(공휴일·휴업일) → 업무. ①②③ 은 학년 태그, 학년 Y/N 값도 쓴다. 같은 이름이 이어지면 기간 하나로(주말 3일, 방학은 7일 이내). 토요휴업일은 `hidden`(날짜 색만).
  - 다시 받기: `ext_source='neis'` 만 지우고 넣는다. 같은 `ext_key`(시작일|이름)가 이미 있으면(교사가 고친 것, 지운 것 `removed`) 넣지 않는다. 교사가 추가한 학사력은 건드리지 않는다.
  - 종류 규칙을 바꾸면 이미 있는 학사력에도 다시 적용한다. 날짜 색은 겹치면 휴일 → 방학 → 휴업일 순(업무만 있는 날은 칠하지 않음).
- **자동 받기**: 앱을 켜고 3초 뒤, 학교가 있으면 시간표·학사일정(키 있을 때)을 하루 한 번, 이번 주 급식을 받는다(`neis_fetches` 에 받은 때·결과를 남김). 인터넷이 안 되면 받아 둔 자료를 쓴다.
- **시간표 색**: `timetable_colors(scope, target, color)` — 칸(학년도-학기|종류|학급|행|요일|교시) → 교과 → 교사 → 학급 → 교실 순(0.9에서 교과·교사 추가, 마이그레이션 0007; 교사는 칸에 교사 이름이 있을 때만). 색 정하기 창도 이 순서로 보이고 처음엔 교과별이 골라져 있다. 색 이름만 저장하고 화면이 15색으로 칠하며, 진한 배경이면 흰 글자. 시간표를 다시 받아도 그대로.

### D17. 오늘 업무 요약과 학생부 자료 영역 7개 (0.9)
- **오늘 업무 요약** (`briefing.rs`)
  - 사실(Fact)을 규칙으로 모은다: 학사력(휴일·휴업일·방학 → 시험 순, 맨 위), 오늘 일정(시간·메모), 오늘 시간표(수업·공강 한 줄, 변경은 따로; 휴일·방학엔 뺌), 오늘 마감 할 일·업무 기록, 기한 지난 할 일(한 줄).
  - 규칙 요약은 늘 바로 만든다(5줄이 넘으면 할 일을 묶고 '그 밖에 n건'). AI 요약은 [새로고침] 때만: 줄마다 근거 번호(refs)가 있어야 하고 근거 사실 대비 2-gram 포함률 0.7 미만인 줄은 버린다. 학사력 줄을 빠뜨리면 맨 위에 붙인다.
  - AI 요약은 (날짜, 사실 해시)와 함께 저장해, 사실이 바뀌면 규칙 요약으로 돌아간다(오래된 요약을 보여 주지 않음).
- **학생부 자료** (`records.rs`)
  - 영역: 창체(자율·자치), 교과, 행특, 동아리, 진로, 자유학기(free_semester), 일상생활(daily) + 출결·봉사. 영역 값 제한(CHECK)을 넓히려고 마이그레이션 0006에서 관찰·초안 표를 다시 만든다. 이때 외래키를 끄고 실행한 뒤 `foreign_key_check` 로 확인한다(id 그대로라 근거 연결 유지).
  - 관찰에 `subject`(교과 과목·자유학기 활동)와 `excluded`(참고자료에서 뺌)를 둔다. 과목은 원문의 과목 이름(긴 것부터) → 그 학생 학급에서 내가 가르치는 과목(개인 시간표)이 하나면 그 과목 → 내 과목이 하나면 그 과목 순으로 정한다.
  - 칸 = (영역, 과목). 칸의 글은 그 칸의 가장 최근 `record_drafts` 행이고, `reviewed=1` 이면 최종안. 상태: 자료 없음/참고자료만/초안/최종안. AI 초안은 빼지 않은 참고자료만 근거로 쓰고 영역 한도를 프롬프트에 넣는다.
  - 한도: 2026학년도 중학교 기재요령 '영역별 입력 가능 최대 글자수'(교육정보시스템, 2026) — 자율·자치·동아리·진로·교과·출결 500자, 행특 300자, 자유학기 활동별·일상생활 1,000자. 바이트는 한글 3, 영문·숫자·엔터 1(2026 기준; 이전 버전은 엔터 2로 셌다).
  - 일상생활 활동상황은 특수교육 기본 교육과정 학생 영역이라 AI가 자동으로 넣지 않는다(원문에 '일상생활'이 있거나 교사가 옮길 때만). AI 분류 영역 목록에는 자유학기만 더했다.
  - 학급 최종안 엑셀: 영역·과목 → 학급·번호 순, 글자 수·바이트·한도 초과 표시.

### D18. 오늘 화면 칸 배치와 메모 (1.0)
- **칸 배치** (`TodayBoard.tsx`, `today_layout.rs`)
  - 칸: 할 일(tasks), 오늘 업무 요약(briefing), 메모(memo), 오늘 시간표(timetable), 급식(meals), 오늘의 기록(notes), 생일·최근 알림(extras). 오늘 화면만 `.content` 최대 너비를 풀어 화면 너비를 다 쓴다.
  - 자동: 칸 묶음 너비로 열 수를 정한다(700px 미만 1열, 1250 미만 2열, 1700 미만 3열, 그 이상 4열). 열마다 정한 칸(AUTO_TEMPLATES)을 놓고 오늘의 기록은 맨 아래 넓은 줄. 열 높이를 맞추고 열마다 마지막 칸을 아래까지 늘려 빈 곳을 없앤다(`:has()` 로 비어 있는 마지막 칸 건너뜀). 측정한 높이로 칸을 옮겨 다니게 하지 않는다(읽는 중에 칸이 움직이지 않게).
  - 직접: 열(1~4)마다 칸 순서, 넓은 줄, 숨긴 칸을 저장한다. 자동에서 처음 옮기면 지금 보이는 배치를 그대로 직접 배치로 옮겨 적는다. 열 하나가 340px보다 좁아지면 순서를 지킨 채 열을 접어 보여 주고(저장된 배치는 그대로) 옮기기는 막는다.
  - 끌어 놓기는 HTML 끌어 놓기 대신 포인터 이벤트로 직접 한다(Tauri 파일 끌어 놓기가 켜져 있으면 WebView2 안의 HTML 끌어 놓기가 오지 않음). 화살표 버튼으로도 같은 일을 할 수 있다.
  - 배치는 설정 표의 `today_layout` 키에 따로 저장한다(앱 설정 저장이 예전 배치로 덮어쓰지 않게). 백엔드에서 모르는 칸·겹친 칸을 빼고 빠진 칸은 마지막 열에 붙인다.
  - 좁은 칸에서는 컨테이너 쿼리로 할 일 줄의 알림 글자를 숨긴다.
- **메모** (`memos.rs`, `MemoPanel.tsx`, 마이그레이션 0008)
  - 날짜와 상관없는 메모(윈도우 스티커 메모처럼). 여러 장, 색 6가지, 새 메모는 맨 앞, 앞뒤로 순서 바꾸기.
  - 글은 쓰는 대로 0.6초 쉬면 저장하고, 칸을 벗어날 때·다른 화면으로 갈 때도 저장한다. 저장해도 data-changed 를 보내지 않는다(화면 전체를 다시 읽지 않게). 메모 칸은 처음 한 번만 읽고 자기 상태로 맞춘다 → 쓰는 중에 다른 자료가 바뀌어도 글이 지워지지 않는다.
  - 지우기는 deleted_at 표시만 하고 [되돌리기]를 보여 준다. 지운 지 30일 지난 메모는 다음에 지울 때 정리한다. 한 장 최대 20,000자.

### D19. 기록 속 개인정보, 출결 탭, AI 진행 표시, 새 항목 숫자 (1.0, 2차 수정목록)
- **개인정보 → 학생 명렬표** (`profile.rs`, 마이그레이션 0009)
  - 전화번호·보호자 연락처(관계 + 번호)·주소·성별·생일·학생개인번호·이전학적은 AI보다 먼저 형식 규칙으로 찾는다. 규칙 분류와 AI 분류(`guard_llm`) 모두 마지막에 `attach_profile` 을 거쳐, 개인정보가 있는 문장의 학생 관찰·할 일·일정 항목을 빼고 `Plan.profile` 로 옮긴다. 학생은 그 문장에 나온 학생 하나, 없으면 기록 전체에서 하나뿐인 학생.
  - 반영(`apply_one`): 빈 칸이면 바로 넣고(applied), 같은 값이면 건너뛰고, 다른 값이면 확인 대기(pending)로 둔다. 보호자 연락처는 `student_contacts` 표(학생마다 4개, 첫 번째는 예전 `guardian_phone` 과 맞춤)에 넣되, 같은 관계가 있으면 그 번호를 바꿀지(target_id), 4개가 찼으면 어느 번호를 바꿀지 묻는다. 모든 변경은 `profile_changes` 에 이력으로 남는다(applied/pending/rejected).
  - 특이사항으로 보이는 문장은 `note_questions` 에 넣고 기록 카드에서 [학생부 자료]/[학생 명렬표 특이사항]을 고르게 한다(다시 고를 수 있음). 출결 표현은 특이사항으로 보지 않는다.
  - 학생부 AI 초안 문맥은 `scrub` 으로 번호·주소를 한 번 더 가린다. 화면 가리기는 명렬표의 '연락처·주소 가리기' 값을 localStorage 와 이벤트로 기록 화면·오늘의 기록과 함께 쓴다.
  - 기록을 다시 분류하면 그 기록에서 나온 대기 건은 지우고 새로 만든다(이미 반영한 값은 그대로).
- **출결 탭** (`records.rs`): 출결 영역을 학생부 탭 맨 앞에 둔다. 참고자료 글에서 종류(결석·지각·조퇴·결과)·사유(질병·미인정·기타·출석 인정)·일수/횟수를 규칙으로 읽어 요약 표를 만든다(뺀 참고자료는 세지 않음). 특기사항 칸은 다른 영역과 같은 흐름이고 한도는 500자.
- **학급명렬표 열 너비** (`RosterTable.tsx`): 학급 64·번호 52·이름 96·기록 84px 고정, 선택 칸은 칸마다 최소·최대·비율로 남는 폭을 나눈다(물 채우기). 모자라면 모두 최소 폭으로 두고 가로 스크롤, 남으면 표 오른쪽 여백. 왼쪽 세 칸은 `position: sticky`.
- **AI 정리 진행 표시** (`app.rs`, `runtime.rs`, `AiProgressRing.tsx`)
  - LLM 은 진행률을 모르므로 단계로 센다: 원문 저장 10 → 이름 대조 25 → AI 분류 25~85 → 안전 규칙 95 → 배치 100. AI 분류 구간은 스트리밍(SSE)으로 받은 글자 수를 기대 길이(min(200 + 3×원문 길이, 1800)자)에 견줘 채운다. 엔진을 켜야 하면 'engine' 단계로 따로 알린다.
  - `classify-progress` 이벤트에 남은 건수를 같이 보낸다. 실패하면 빨간 게이지와 [다시 시도]/[기록 보기].
- **새 항목 숫자** (`seen.rs`, `lib/seen.ts`)
  - 설정 표의 `seen_marks` 에 메뉴별(학생부 자료·교무 업무·할 일·학생 명렬표) 마지막으로 본 시각을 둔다. 처음 쓰는 날은 지금으로 잡아 업데이트 전 항목을 새 항목으로 세지 않는다.
  - 숫자 = AI 가 넣은(source='ai') 항목 중 그 시각 뒤에 만든 것. 지운 항목은 빠지고, 다시 분류돼 다른 메뉴로 가면 새로 만든 항목이라 그 메뉴에서 센다. 할 일은 끝낸 것을 빼고, 학생 명렬표는 반영된 개인정보 변경만 센다.
  - 메뉴를 열면 시각을 지금으로 바꾸고 이전 시각을 돌려받아, 이번 방문 동안만 그 뒤 항목에 '새'·점 표시를 한다(학생부 자료: 학생 이름·영역 탭·학급 제목줄).
  - 기록 메뉴 숫자(회색)는 정리 중·미분류 + 답할 것(특이사항 질문·개인정보 확인), 새 항목 숫자는 초록 동그라미.

## 3. 플랫폼 분리
Windows 전용 코드는 `#[cfg(windows)]`로 모았다: Job Object(runtime.rs), 수신 주소 확인(runtime.rs), 알림·자동 시작(notify.rs), DXGI GPU·저장 공간(device.rs, models.rs), 메시지 상자(lib.rs).
다른 OS에서는 같은 함수가 "아직 지원하지 않음"을 돌려주도록 대체 구현을 두었다 (macOS Apple Silicon 확장 대비).

## 4. 쓰지 않은 선택지
- Electron: 배포 크기·메모리 (명세 제외).
- AI에게 날짜 계산 맡기기: 작은 모델은 요일 계산을 자주 틀린다 → 규칙으로 계산.
- 공식 llama.cpp 바이너리 그대로 쓰기: VC++ 런타임 의존 (D6).
- 앱이 꺼져 있을 때도 알림 보장(Windows 작업 스케줄러 등록): 학교 PC 정책에서 막히는 경우가 많고 관리가 어렵다 → 선택형 자동 시작·트레이로 대신하고 한계를 설정 화면에 적었다.
- GPU 가속: 1차 대상(외장 GPU 없는 학교 PC)과 크기·의존성(VC++ 런타임)을 고려해 이번에는 넣지 않았다(사용자 결정).
