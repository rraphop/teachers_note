## 6. Windows 보안(Defender)

- 1.0 첫 빌드의 파일 하나 버전(묶음을 압축해 넣은 32MB 실행기)을 Windows 보안이 `Trojan:Win32/Sabsik.FL.A!ml`(기계학습 추정 판정)로 잡아 격리했다. 같은 빌드의 본체·AI 엔진·ZIP 은 깨끗했다.
- 묶음을 압축하지 않은 실행기(85MB)는 같은 검사에서 깨끗했고, 바탕화면에 복사한 뒤에도 지워지지 않았다. 그래서 묶음을 압축하지 않기로 했다.
- 패키징 10단계에서 `MpCmdRun -Scan -DisableRemediation`(격리하지 않고 검사만)으로 실행기·ZIP·본체를 검사하고, 탐지되면 패키징을 멈춘다.
- 판정 모델은 바뀔 수 있으므로 근본 해결은 코드 서명이다 → `LIMITATIONS.md` 1번.

## 7. 개인정보·안전

- AI 엔진은 127.0.0.1 에서만 연결을 받고 실행할 때마다 새 인증키를 쓴다(엔진 시험·평가에서 연결 주소 확인).
- 나이스로 보내는 값은 학교 코드·날짜(와 넣은 경우 인증키)뿐임을 시험용 서버에서 요청 내용을 받아 확인했다(학생 정보 없음).
- 프로그램을 강제로 끝내도 AI 엔진이 남지 않는다(Job Object, `run-engine.mjs`).
- 자동 시험은 실제 시작 프로그램 목록(레지스트리 Run)을 건드리지 않고 시험용 키를 쓴다. 시험 전후로 실제 목록이 같음을 확인했다.
- 데이터 폴더는 0.1 부터 1.0 첫 배포까지 `%LOCALAPPDATA%\TeacherNotebookV2` 였고, 이후 `%LOCALAPPDATA%\teachers_note` 로 이름을 바꿨다(켤 때 예전 폴더를 그대로 옮김, 기록·모델·백업 유지). 새 버전이 데이터 형식을 올리기 전에 ‘업데이트 전’ 백업을 만든다(0.9→1.0 시험에서 확인).
